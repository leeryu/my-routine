# 내 루틴 개선 기획안 (2026-09-23)

작성 관점: 헬스 트레이너 + 앱 기획. 기준 커밋 `7564f83` (A=화 / B=목 상체 근비대 개편 직후).
모든 판정은 코드 라인 근거 + 실행 검증(Playwright 390×844 렌더, progression.js 직접 호출) 기반. 근거 없는 건 "모름"으로 표기.

## 0. 결론

1. **프로그램 설계 자체는 양호**, 문제는 앱이 그 설계를 못 따라감. 주간 직접세트(가슴 7 / 등 11 / 측면 7 / 후면 5 / 이두 4 / 삼두 2)는 목표치와 정확히 일치.
2. **증량 신호가 사실상 절대 안 뜸** (P0). A·B가 같은 종목 이력을 공유하는데 세트 수·반복 범위가 달라서 "2회 연속 상한 달성" 조건이 매주 끊김.
3. **주간 일정 소스가 3곳에서 서로 다름** (P0). 화요일(A 헬스일)에 데일리 탭은 "홈코어 / 휴식일 칼로리"를 표시.
4. **컨디션 점수는 가짜 값** (P0). 입력 UI가 없어서 항상 72점이고, 이 값이 Notion·AI 코칭 컨텍스트로 전송됨.
5. **헬스장에서 첫 종목까지 1,300px 스크롤** (844px 화면 약 1.5장). 세트 1개가 약 260px이라 4세트 종목 하나가 한 화면을 넘음.
6. 제거 후보 7개(플레이트 계산기, 연속일 streak, 톤수 기반 근육 코칭 등), 추가 후보 10개(홈코어 루틴, 수영 완료 로그, 종목별 증량 단위 등).

## 1. 사용자 최적화 진단

전제로 둔 사용자 프로필(코드에서 추출): 주 2회 상체 헬스(A 화 / B 목), 주 1~2회 수영(토 메인 / 일 기술), 재활의학과 소견(코어 안정성 부족, 경미한 기능성 골반 전방경사, 거북목), 하체는 증상 기반으로 재도입 중, 단백질 130~140g.

| 영역 | 평가 | 근거 |
|---|---|---|
| 프로그램 구성 | 양호 | A 헤비(6~10, RIR 1~2) / B 수영 회복용(RIR 2~3)으로 역할 분리가 명확함. 볼륨은 초보자 기준 적정 하한 |
| 증량(진행) 엔진 | **결함** | 2.1~2.4 참고. increase 상태 도달 불가 |
| 일정 일관성 | **결함** | 2.5 참고 |
| 회복·컨디션 반영 | **가짜 데이터** | 2.6 참고 |
| 재활·코어 | 부족 | 임상 목표가 "코어 안정성"인데 홈코어 콘텐츠·기록이 0. 하체 트래커는 헬스 루틴과 따로 놂 |
| 수영 연동 | 부족 | 수영 "완료" 개념이 없음. 주간 스트립·출석에 안 잡힘. 기록 항목이 SWOLF·스트로크 수뿐 |

## 2. P0 — 버그·로직 결함 (신뢰성 문제라 최우선)

**2.1 A/B 교차 이력 때문에 증량 판정 불가**
- 원인: `getExHistory()`가 `exerciseId`로만 필터함 (`js/app.js:779`). 그래서 A 체스트 프레스(4세트, 6~10회)의 "직전 세션"이 목요일 B 체스트 프레스(3세트, 8~12회)가 됨.
- `isStableTop(B기록, A종목)`은 4번째 세트를 찾지만 B 기록엔 세트가 3개뿐이라 0회로 계산되고 false가 됨 (`js/progression.js:106`, `:120`).
- 검증 결과: A가 2주 연속 40kg×10×4(RIR 2)를 해도 중간에 B가 끼면 `top-once`에서 멈춤. B가 없을 때만 `increase`.
- 부작용: 반복수 증감도 노이즈가 됨. A 35회 vs 직전 B 36회는 "하락"으로, B 36회 vs 직전 A(3세트분 27회)는 "+9"로 표시됨.
- 영향 종목: 체스트 프레스, 랫풀다운, 덤벨 로우, 레터럴, 리버스 펙덱 (세트 수가 A와 B에서 다른 종목 전부).
- 수정: 진행 판정과 프리필은 **같은 routineKey + exerciseId** 이력만 쓰도록 변경. PR·차트는 기존처럼 통합해도 됨.

**2.2 RIR 조건 결함**
- `rir === '1' || rir === '2'`일 때만 상한 달성으로 인정함 (`js/progression.js:106`).
- RIR 3+로 상한 반복을 채우면 = 너무 가벼움 = 가장 빨리 증량해야 하는 케이스인데, 영원히 "유지"로 나옴 (검증 완료).
- B 루틴은 팁 문구가 "RIR 2~3"이라 목표대로 하면 증량 판정에서 빠짐.
- RIR을 입력 안 해도 영원히 유지. RIR 선택은 카드 하단 select에 숨어 있음.
- 수정: 상한 달성 + RIR ≥ 1이면 인정. RIR 3+는 1회만으로도 증량 추천. RIR 0은 유지. RIR 미입력이면 마지막 세트 체크 시 칩 4개(0/1/2/3+)를 강조 노출.

**2.3 증량 추천에 숫자가 없음**
- INCREASE일 때 `kg: 0`으로 반환해서 적용 버튼이 안 뜨고 "다음 최소 중량을 고려하세요"라는 문구만 나옴 (`js/app.js:833`).
- ± 버튼은 모든 종목이 2.5kg 단위 (`js/app.js:1332`). 레터럴 6kg에 +2.5를 하면 8.5kg이 되는데, 이런 덤벨은 없음.
- 수정: 종목별 `increment` 필드 추가(덤벨 1~2kg, 머신 스택 2.5~5kg — 기구마다 다르니 사용자가 설정). 증량 추천은 "현재 + increment kg, 반복은 repMin부터"로 구체화하고 1탭으로 적용.

**2.4 정체 감지가 더블 프로그레션과 충돌**
- `detectPlateau()`는 최근 3~4세션의 **중량**만 봄 (`js/app.js:811-822`). 더블 프로그레션에선 같은 중량으로 반복수를 쌓는 게 정상이라 거의 매번 "정체"로 뜸.
- 정체 경고가 코치 추천보다 우선이라(`js/app.js:1366`) 진행 메시지까지 가려짐.
- 처방 문구 "휴식 단축 시도"는 근비대 목적엔 역효과임(휴식 단축 → 세트당 수행 반복 감소).
- 수정: 중량과 총반복이 모두 3세션 정체일 때만 경고. 처방은 수면·단백질 확인 → 세트 1개 추가 → 종목 변형 순서로.

**2.5 주간 일정 소스 3곳 불일치**

| 위치 | 월 | 화 | 수 | 목 | 토 | 일 |
|---|---|---|---|---|---|---|
| `DAY_INFO` (주간 스트립, `app.js:237`) | 휴식/코어 | **A** | 코어/휴식 | **B** | 메인수영 | 기술수영/휴식 |
| `WEEKLY_SCHEDULE_BASE` (데일리·칼로리, `app.js:2995`) | **헬스A**+홈코어 | 홈코어 | **헬스B** | 홈코어/휴식 | 수영 45~60 | 수영 60~90 |
| 월요일 회복 체크 (`app.js:3072`) | "A를 화요일로 이동" | — | — | — | — | — |

- 결과(스크린샷 확인): 화요일 A 헬스일에 데일리 탭은 "화 = 홈코어", 칼로리는 휴식일 2,050~2,150kcal을 표시. 헬스일 목표(2,250~2,300kcal) 대비 약 200kcal 과소.
- 월요일 회복 체크는 A가 이미 화요일이라 의미가 없어짐. 전체를 하루씩 미는 로직(`shiftScheduleForRecovery`)은 B를 금요일로, 토 수영을 일요일로 밀어버림.
- 수정: `WEEK_PLAN` 상수 하나로 통합하고 스트립·데일리·칼로리·자동 루틴 선택·회복 체크가 전부 여기서 파생되게. 회복 체크는 "A 당일(화) 아침 → 해당 시 A를 수요일로 1일 이동, B는 목요일 유지(48h 확보되면)"로 재정의.

**2.6 컨디션(readiness) 가짜 값**
- 입력 UI(`rdSleep`, `readinessCard`, `coachPanel`)가 `index.html`에 없음. `renderReadiness()`와 `updateCoachPanel()`은 할 일이 없는 함수가 됨.
- 입력이 없으면 기본값 {수면 3, 피로 3, 통증 1} → 72점 고정 (검증 완료).
- 이 값이 코치 메시지, 완료 화면 "회복점수 72", Notion 이벤트의 `readiness`와 AI 코칭 프롬프트에 그대로 들어감 (`app.js:1129-1137`). 매번 같은 거짓 컨텍스트가 AI에 전달되는 셈.
- 수정(택1): (A) 운동 시작 CTA 위에 3탭 체크인(수면·피로·통증 각 1~5) 복구 + 미입력 시 전송값을 `null`로. (B) readiness 기능 제거. 트레이너 의견은 **A**. 재활 이력이 있으면 통증 추세가 가장 가치 있는 데이터임.

**2.7 기타 데이터 불일치**
- 완료 조언은 "단백질 120g 근처"(`app.js:1865`)인데 칼로리 표는 130~140g.
- B 덤벨 로우 팁은 "A보다 가볍게"인데 기본 중량이 B 20kg > A 16kg (`app.js:197`, `:210`). 첫 기록에만 영향.
- 리버스 펙덱은 `MUSCLE_MAP`에서 후면어깨와 등 양쪽에 볼륨 100%씩 이중 집계됨 (`app.js:256`).

## 3. 트레이너 관점 — 프로그램 최적화

**볼륨**: 현재 볼륨 유지를 권장. 초보자·재활 이력이 있고 수영이 등·어깨에 추가 부하를 주는 조건이라, 세트를 늘리는 것보다 2.1~2.3을 고쳐서 **실제로 증량이 돌아가게 하는 쪽이 ROI가 압도적**임. 가슴·측면이 주 7세트로 근비대 연구상 권장선(주 10세트 이상, Schoenfeld 2017 메타분석) 아래이긴 함. 증량 루프가 4주 이상 정상 작동한 뒤에도 정체하면 A 체스트 프레스 +1세트부터 늘리기.

**휴식시간**: 지금은 전 종목 90초이고 RIR 0일 때만 120초 (`app.js:1600`). 근비대 기준으로 복합 종목(체스트/숄더 프레스, 로우, 랫풀)은 2~3분, 고립 종목(레터럴, 펙덱, 컬, 푸쉬다운)은 60~90초가 적정(Schoenfeld 2016 등). 종목별 `restSecs` 기본값을 추가.

**홈코어**: 임상 목표(갈비뼈-골반 중립, 코어 안정성)가 이 앱에서 유일하게 콘텐츠가 없는 영역임. 월·수가 "코어" 일정인데 할 게 표시 안 됨. 10분짜리 체크리스트 루틴을 추가:

| 종목 | 처방 | 목적 |
|---|---|---|
| 90/90 호흡 | 5호흡 × 2 | 갈비뼈 하강, 중립 인지 |
| 데드버그 | 3 × 6~8/측 | 항신전 (골반 전방경사 대응) |
| 버드독 | 3 × 6~8/측 | 요추 중립 유지하며 사지 분리 |
| 글루트 브릿지 | 3 × 10~12 | 둔근 활성, 골반 후방 제어 |
| 팔로프 프레스(밴드) | 2 × 10/측 | 항회전 |

- 사이드 플랭크는 과거 "오른쪽 금지" 경고가 있었음 → 현재도 유효한지 **모름**. 재활 담당자 확인 전엔 제외.
- 위 표는 일반적인 전방경사·코어 부족 처방 예시임. 개인 처방은 담당 재활의학과·필라테스 강사 기준이 우선.

**필라테스·재평가**: 진료 권고가 "필라테스 주 1회 × 8주"(2026-07-27 평가)였는데 8주 기간이 **2026-09-21에 종료**됨. 실제로 수행 중인지는 **모름**. 재평가 리마인더를 넣을 시점.

**하체**: 레그 익스텐션(헬스 루틴)과 하체 재도입 트래커(데일리 탭, 스쿼트→레그프레스→런지 5단계)가 서로 연결이 없음. 레그 익스텐션 카드 목표가 "현재 재도입 단계"라고만 되어 있고 단계는 표시 안 됨. 헬스 루틴 마지막 카드를 "하체 재도입 STAGE n" 카드로 대체하고, 4개 체크를 세트 완료 직후 인라인으로.

**수영 연계**: B 루틴을 수영 회복용으로 설계한 건 좋음. 다만 수영 부하가 앱에 안 잡혀서 주간 부하 판단이 불가능함. 수영 완료 + 거리·시간·RPE 입력(SWOLF는 선택)을 추가하고 주간 스트립에 체크 표시.

## 4. UI/UX 개선

**4.1 운동 탭 재배치 (가장 큰 체감 개선)**

현재 첫 종목 앞에 쌓인 블록(측정 기준 1,300px): 헤더+진행 링 → 주간 스트립 → 시작 CTA → 휴식 타이머 대형 카드(대기 중 1:30) → 요약 3칸 → 코치 넛지 → 루틴 선택 3칩 → 종목 개요 그리드 → 섹션 헤더.

| 프리필 값 초록 배경 → 회색 + "지난번" 라벨 | 초록은 "완료/확정"으로 오인됨 |
| 루틴 자동 선택 + 헤더에서만 변경 | 루틴 선택 칩 제거. 요일 기반 자동 선택은 이미 있음 |
| C루틴 칩 제거 | "기본 일정 제외" 레거시. 데이터는 기록 탭에서 보존 |
| 휴식·수영·코어일 전용 카드 | 현재는 휴식일에도 A 루틴이 뜨고 "첫 운동 시작" CTA가 나옴 |
| 테마 버튼(fixed) → 설정 탭 + `prefers-color-scheme` | 스크린샷상 스트립·데일리 행을 가림 |

**4.2 코치 메시지 5곳 → 2곳**

현재 위치: 상단 코치 넛지, 종목 카드 top-insight, "로컬 코치 피드백" 버튼, 주간 코치 리포트, 완료 배너 조언. 같은 내용이 반복되고 말투도 제각각임. 종목 카드 1줄 추천(행동 + 숫자 + 적용 버튼)과 완료 요약(다음 세션 예고) 두 곳만 남김.

**4.3 기록 탭 9섹션 → 4섹션**

| 신규 섹션 | 흡수 대상 |
|---|---|
| 이번 주 | 주간 요약, 주간 코치 리포트(직접세트·진행 상태), 출석 |
| 종목 진행 | 진행도 차트 + PR 보드 (종목 선택 1회로 둘 다) |
| 몸·영양 추세 | 7일 평균 체중, 나트륨, (추가) 단백질 달성률 |
| 최근 기록 | 최근 운동 로그 (탭 시 상세) |

- PR은 중량 PR만 있어서 더블 프로그레션에선 거의 안 갱신됨. "같은 중량 최다 반복" PR을 추가.
